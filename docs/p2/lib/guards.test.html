Eight invariants, and the proof that each one throws.

Every guard below is run twice: once against something it must allow, once against the exact thing it exists to forbid. A guard that passes its failing case is broken, and a broken guard is worse than none, because the next person trusts it. Where a check is a heuristic rather than a guarantee, its section says so and its known misses are on the page as passing rows.

Run it live
From the repo root: python3 -m http.server 8000, then http://localhost:8000/docs/p2/lib/guards.test.html. That reads the six real frozen files and checks the census rows as well.
Run it offline
Open this file directly. Browsers refuse ES modules over file://, so the page will say so and tell you the command above. There is no way around that in a browser and no reason to work around it — the served run is the real one.
What a red row means
Either a guard stopped throwing on the thing it forbids, or the frozen record moved under it. Both are stop-the-build. Read the message: every guard names the rule, the offending value and what to do instead.
What ADVICE, NOT A GUARANTEE means
G7's text lint returns findings and never throws. Its section carries two sentences it misses, as passing rows, so that a green page is never read as "the prose is clean". The guarantee for G7 is assertSimulatorMechanismScopes(), which checks 21 frozen scenario records against a declared vocabulary and cannot be paraphrased around.
Adding a guard
Add it to GUARDS in guards.js with its why, then add a passing and a failing case to CASES in this file. The page builds itself from those two lists.
